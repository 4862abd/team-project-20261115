# 요구사항 정의서

## 1. 프로젝트 개요

| 항목      | 내용                                                                                                                |
| ------- | ----------------------------------------------------------------------------------------------------------------- |
| 프로젝트명   | sumnote-20261115                                                                                                  |
| 한 줄 설명  | PDF, TXT, DOCX, XLSX, XLS, CSV 문서를 요약하고 결과 파일을 제공하는 프로그램                                                          |
| 프로젝트 목적 | AI가 문서의 핵심 내용을 요약하고 검증 결과를 제공해 문서 검토를 효율적으로 돕는다.                                                                  |
| 프로젝트 배경 | 다양한 문서를 빠르게 검토해야 하는 상황에서 문서의 양이 많으면 핵심 내용을 파악하는 데 시간이 오래 걸리고 중요한 정보를 놓칠 수 있다. 이 문제를 AI Agent를 활용해 효율적으로 처리하고자 한다. |
| 개발 기간   | 3시간                                                                                                               |
| 팀원      | 4명                                                                                                                |

## 6. 처리 흐름

| 순서 | 단계        | 설명                                     |
| -- | --------- | -------------------------------------- |
| 1  | 문서 업로드    | 사용자가 지원 형식의 문서 또는 스프레드시트를 업로드한다.       |
| 2  | 업로드 제한 확인 | 확장자로 지원 형식을 확인하고, 업로드 시 파일 크기 10MB 이하인지 확인한다. |
| 3  | 내용 추출 및 제한 확인 | PDF는 텍스트 추출 후 실제 페이지 수 20페이지를 확인한다. TXT·DOCX·Excel은 페이지 제한 없이 용량만 확인하며, 스프레드시트는 표시 시트 수를 확인한다. |
| 4  | 내용 분석 | 문서 또는 스프레드시트의 내용을 읽고 요약 및 검증 결과를 만든다. |
| 5  | 결과 파일 생성 | 입력 유형에 대응하는 PDF 또는 XLSX 결과 파일을 만든다. |
| 6  | 결과 다운로드 | 생성 완료 후 다운로드 응답을 제공한다. |
| 7  | 처리 데이터 폐기 | DB와 임시 파일에 저장하지 않는다. 실패 시 즉시 폐기하고, 성공·취소 시점은 초안 가정에 따른다. |

## 7. 출력 결과

### 7.1 문서 입력 결과 (PDF)

PDF 결과에는 다음 승인된 항목을 포함한다. 페이지 레이아웃과 디자인 세부사항은 미정이다.

1. 문서 제목
2. 전체 요약
3. 중요도에 따른 대·중·소단락 핵심 내용
4. 주요 인물·기관명, 날짜, 수치 등 핵심 정보
5. 검증 결과: 확인 항목, 결과, 근거가 된 원문 위치 또는 내용

요약과 검토 후보는 중요도에 따라 계층형으로 구성한다. 원문 근거는 LLM AIagent API 결과를 사용한다. 중요도 단계의 세부 기준과 API 근거 필드 형식은 구현 단계에서 정한다.

초안 서식: A4 세로 방향으로 구성하고, 제목·전체 요약·계층형 본문·검증 표·페이지 번호를 포함한다.

### 7.2 스프레드시트 입력 결과 (XLSX)

XLSX 결과는 요약 결과 중심으로 구성하며, 아래 시트 구성을 사용한다. 입력 데이터는 결과 파일에 요약 정보로 반영한다.

| 시트명    | 헤더                             | 내용                                   |
| ------ | --------------------------------- | ------------------------------------ |
| 전체 요약  | 항목, 요약 내용, 검증 결과                  | 통합 문서 또는 CSV 데이터의 전체 요약 및 검증 결과      |
| 시트별 요약 | 원본 시트명, 헤더, 데이터 행 수, 주요 내용, 검증 결과 | 표시 시트별 구조와 요약. CSV는 단일 데이터 시트로 취급한다. 숨김 시트는 요약 대상에서 제외한다. |

## 제약과 데이터 취급

* 허용 입력 확장자: `.txt`, `.docx`, `.pdf`, `.xlsx`, `.xls`, `.csv`.

* 파일당 최대 크기: 10MB.

* 모든 지원 확장자의 업로드 용량 제한은 파일당 10MB다.
* PDF는 텍스트만 추출하며 OCR은 하지 않는다. PDF는 텍스트 추출 단계에서 실제 페이지 수를 확인하고 최대 20페이지로 제한한다.
* TXT·DOCX·XLSX·XLS·CSV는 페이지 제한 없이 용량만 확인한다.

* 스프레드시트는 숨김 시트를 요약 대상에서 제외하고, 표시 시트 최대 10개로 제한한다. CSV는 1개 시트로 계산한다.

* 원본과 요약 결과는 DB에 저장하지 않는다.

* 처리용 임시 파일도 저장하지 않는다. 실패 시 관련 메모리 자료를 즉시 폐기한다.
* 초안 가정: 성공 시 다운로드 응답 완료 후, 사용자 취소 시 취소 확인 즉시 메모리 자료를 폐기한다.

## 11. 결과 표시 기능 요구사항

이 절은 기존 요구사항에 결과 표시 기준을 추가한다. 기존 결과 화면 코드는 저장소에서 확인할 수 없어, 아래 내용은 구현 상태가 아니라 요구사항이다. `MVP-plan.md`에는 내용이 없다. 기존 §10 및 PDF 서식에 있는 관련 초안은 이 절의 결정사항으로 보완한다.

### 11.1 표시 목적과 범위

- 앞 단계에서 생성된 문서 정보, AI 요약 결과, 원문 근거, AI 검증 결과를 사용자가 확인하도록 한다.
- 결과 표시 화면에서 새 AI 분석·요약·검증을 실행하지 않는다.
- PDF·DOCX·TXT·XLSX·XLS·CSV의 결과는 지원 입력 형식에 따라 표시한다.
- 화면은 데스크톱 기준으로 정의한다. 모바일 전용 기능 및 모바일 레이아웃 구현은 범위에서 제외한다.

### 11.2 필수 표시 항목

아래 항목을 결과 화면에 표시한다. 항목에 값이 없으면 빈칸으로 두지 않고 `없음`을 표시한다.

| 영역 | 필수 표시 항목 |
| --- | --- |
| 문서 정보 | 문서명, 입력 파일 형식 |
| 요약 | 한 줄 요약, 핵심 내용, 주제, 키워드, 수치·조건 |
| 원문 근거 | 요약 또는 검토 항목을 뒷받침하는 원문 근거. 요약과 시각적으로 구분한다. |
| 검토 항목 | 사람이 최종 확인해야 할 항목과 그 근거 |
| 검증 상태 | AI 검증 결과가 생성되었는지 여부 및 결과 상태 |

요약 내용과 원문 근거는 같은 문장처럼 섞어 표시하지 않는다. 별도 영역에서 각각 구분해 확인할 수 있어야 한다.

### 11.3 화면 구성과 탐색

- 문서명과 입력 형식은 결과 화면 상단에 표시한다.
- 결과는 `요약`, `원문 근거`, `검토 항목` 탭으로 구분한다.
- 한 번에 하나의 탭과 한 페이지를 표시한다. 한 페이지의 내용은 화면 한 영역에 맞추며, 긴 결과는 세로 스크롤 대신 페이지 이동으로 확인한다.
- 한 페이지에 표시할 항목 수는 고정값으로 제한하지 않는다. 내용이 화면 영역을 넘으면 다음 페이지로 나눈다. 항목과 해당 근거가 서로 떨어지지 않도록 같은 페이지에 배치한다.
- 결과 화면에서 `새 문서 업로드`를 선택하면 현재 결과를 비우고 첫 업로드 화면으로 돌아간다.

### 11.4 상태별 표시

| 상태 | 화면 표시 및 안내 |
| --- | --- |
| 완료 | `완료` 상태와 생성된 요약·근거·검토 항목을 표시한다. |
| 일부 근거 확인 필요 | `일부 근거 확인 필요` 상태를 표시하고 확인 대상과 확인 가능한 근거를 구분해 보여 준다. |
| 실패 | `실패` 상태와 확인 가능한 실패 사유를 표시하고, 사용자가 재시도 여부를 선택하게 한다. |
| 결과 없음 | `결과 없음` 상태를 표시한다. 값이 없는 항목에는 `없음`을 표시하고, 사용자가 재시도 여부를 선택하게 한다. |
| AI 검증 결과 미생성 | 요약 결과 상태와 별도로 `검증 결과 없음`을 표시한다. 검증 미생성을 정상 검증 결과로 오인하게 표시하지 않는다. |

### 11.5 관찰 가능한 수용 기준 및 추적

| 사례 | 수용 기준 | 기존 ID 연결 |
| --- | --- | --- |
| 정상 | 문서명·형식 및 필수 요약 항목이 표시되고, 요약과 원문 근거가 별도 영역에서 확인된다. | R-03, T-03, SUM-07 |
| 경고 | 일부 근거 확인이 필요한 항목이 상태로 표시되고, 해당 항목과 확보된 근거를 식별할 수 있다. | R-04, T-04, VER-05 |
| 오류 | 실패 사유가 표시되고, 사용자가 재시도 여부를 선택할 수 있다. | R-01~R-04의 예외 흐름 |
| 결과 없음 | 결과 없음 상태와 빈 항목의 `없음` 표시가 나타나며, 재시도 여부를 선택할 수 있다. | R-03, R-04 |
| 검증 미생성 | 요약은 표시하되 검증 영역에 `검증 결과 없음`을 표시한다. | R-04, VER-05 |
| 긴 결과 | 탭과 페이지 이동으로 전체 결과를 확인하며, 결과 영역의 세로 스크롤에 의존하지 않는다. | 결과 표시 세부 기준 추가 |
| 새 문서 업로드 | 새 문서 업로드를 선택하면 이전 결과가 화면에서 지워지고 첫 업로드 화면으로 이동한다. | 결과 표시 세부 기준 추가 |
| 모바일 | 모바일 전용 레이아웃이나 기능을 요구하지 않는다. | 범위 제외 |

관련 기존 ID는 `R-03`, `R-04`, `T-03`, `T-04`와 기능분해서의 `SUM-07`, `VER-05`다. 결과 표시 전용 R-ID/T-ID는 새로 만들지 않았다.

## 12. 결과 다운로드 기능 요구사항

이 절은 기존 요구사항에 PDF 결과 다운로드 세부 기준을 추가한다. 현재 Frontend·Backend 코드와 결과 데이터 구조는 저장소에서 확인할 수 없으므로 아래 내용은 현재 구현 사실이 아니라 요구사항이다. 기존 요구사항은 `.txt`, `.docx`, `.pdf` 입력의 PDF 결과와 `.xlsx`, `.xls`, `.csv` 입력의 XLSX 결과를 정의한다. PDF 다운로드는 필수로 포함한다.

### 12.1 다운로드 가능 화면과 상태

- 결과가 표시되는 화면에서 PDF 다운로드를 제공한다.
- 완료, 일부 근거 확인 필요, 검증 미생성, 실패 또는 결과 없음 상태에서도 PDF 다운로드를 허용한다.
- 결과가 일부만 생성되었거나 검증 결과가 없으면 생성된 내용과 상태를 포함해 다운로드한다. 전체 분석이 실패했으면 확인 가능한 문서 정보와 실패/결과 없음 상태를 담은 PDF를 제공한다.
- Excel 입력은 기존 요구사항에 따른 XLSX 결과도 제공한다. PDF는 다운로드 가능한 형식에 반드시 포함한다.

### 12.2 PDF 포함 내용과 구분

PDF에는 다음 내용을 포함한다.

1. 문서명과 입력 형식
2. 생성된 한 줄 요약, 핵심 내용, 주제, 키워드, 수치·조건
3. 생성된 검토 항목
4. 요약·검토 내용을 뒷받침하는 원문 근거
5. 완료·경고·실패·결과 없음 및 검증 미생성 상태

- 요약과 원문 근거를 시각적으로 분리한다.
- 원문 전체는 PDF에 포함하지 않는다. 근거에 필요한 원문 발췌와 확인 가능한 출처 정보만 포함한다.
- 일부 항목이나 근거가 없으면 `없음`으로 표시한다. 검증 결과가 없으면 `검증 결과 없음`으로 표시한다.

### 12.3 페이지 구성과 읽기 순서

- 중요도 순으로 배치한다: 문서 정보, 한 줄 요약과 핵심 내용, 주제·키워드·수치·조건, 검토 항목과 각 항목의 원문 근거.
- 관련 근거는 해당 요약·검토 항목 가까이에 배치해 대응 관계를 확인할 수 있도록 한다.
- PDF 페이지 크기와 세부 서식은 기존 초안인 A4 세로 구성을 기본안으로 제안한다. 이는 사용자 답변에서 별도로 확정되지 않은 시각 서식 기본값이다.

### 12.4 파일명, 보관 및 오류 처리

| 항목 | 요구사항 |
| --- | --- |
| PDF 파일명 | 원본 파일명에서 확장자를 제외한 이름 뒤에 `_summary.pdf`를 붙인다. 사용자가 내려받은 파일의 보관과 이름 변경은 사용자 책임이다. |
| 사용자에게 표시할 파일 정보 | 다운로드 항목에 생성된 파일명과 형식(PDF)을 표시한다. Excel 결과의 XLSX도 제공될 때에는 XLSX 파일명과 형식을 별도로 표시한다. |
| 보관 기간 | 애플리케이션은 문서·결과를 DB나 임시 파일로 보관하지 않는다. 다운로드된 파일의 보관은 사용자가 관리한다. |
| 제공 방식 | PDF 생성이 끝나면 결과 화면에서 즉시 다운로드할 수 있게 한다. 다운로드 후 장기 보관이나 과거 결과 재조회는 제공하지 않는다. |
| PDF 생성·다운로드 실패 | 실패 사유를 안내하고 자동 재시도하지 않는다. 사용자가 재시도 여부를 선택한다. |

### 12.5 관찰 가능한 수용 기준 및 추적

| 사례 | 수용 기준 | 기존 ID 연결 |
| --- | --- | --- |
| 정상 다운로드 | PDF를 내려받을 수 있고 문서 정보, 생성된 요약, 근거가 포함된다. 원문 전체는 포함되지 않는다. | R-01, R-02, T-01 (문서 입력 PDF), OUT-01~OUT-03. Excel 입력 PDF에는 기존 T-ID 없음 |
| 일부 근거 누락 | PDF 다운로드가 허용되고 누락 항목에는 `없음`을 표시한다. | R-04, T-04, OUT-01~OUT-03 |
| 검증 결과 미생성 | 요약이 있으면 PDF를 내려받을 수 있고 검증 영역에 `검증 결과 없음`을 표시한다. | R-04, T-04, VER-05, OUT-01~OUT-03 |
| 실패 또는 결과 없음 | PDF 다운로드가 허용되고 확인 가능한 문서 정보와 실패/결과 없음 상태를 포함한다. | R-01~R-04, OUT-01~OUT-03 |
| PDF 생성·다운로드 오류 | 오류 안내가 표시되고 사용자가 재시도 여부를 선택할 수 있다. | 기존 오류 처리 기준; 전용 ID 없음 |
| Excel 입력 | XLSX 결과와 PDF 결과를 제공한다. 기존 T-02는 XLSX 출력 기준에 연결한다. | R-02, T-02 (XLSX 결과), OUT-01~OUT-03. Excel 입력 PDF에는 기존 T-ID 없음 |

관련 기존 ID는 `R-01`, `R-02`, `R-04`, `T-01`, `T-02`, `T-04`와 기능분해서의 `VER-05`, `OUT-01`~`OUT-03`이다. 새 R-ID/T-ID는 만들지 않았다.
