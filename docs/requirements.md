# 요구사항 정의서

## 1. 프로젝트 개요

| 항목      | 내용                                                        |
| ------- | --------------------------------------------------------- |
| 프로젝트명   | sumnote-20261115                                          |
| 한 줄 설명  | 문서를 업로드하면 내용을 요약·분석하고 결과를 대시보드로 제공하는 서비스                  |
| 프로젝트 목표 | 긴 문서를 빠르게 파악할 수 있도록 요약 결과를 제공하여 문서 확인 시간을 줄이고 업무 효율을 높인다. |
| 개발 기간   | 3시간                                                       |
| 팀원      | 4명                                                        |

## 2. 해결하고자 하는 문제

| 항목            | 내용                                                 |
| ------------- | -------------------------------------------------- |
| 현재 문제         | 다양한 문서를 읽고 요약·정리하는 데 많은 시간이 들며, 중요한 내용을 빠뜨리기 쉽다.   |
| 사용자가 겪는 불편    | 문서의 양이 많을수록 내용을 파악하고 핵심 정보를 정리하는 데 시간과 노력이 많이 든다.  |
| 이 서비스가 제공할 가치 | 문서의 핵심 내용을 빠르게 파악하고, 요약 결과와 검토 필요 사항을 확인할 수 있게 한다. |

## 3. 대상 사용자

| 사용자 유형 | 설명                      | 주요 상황                    |
| ------ | ----------------------- | ------------------------ |
| 사무직원   | 업무 문서를 읽고 보고서를 작성하는 사용자 | 처리해야 할 문서가 많고 문서 유형이 다양함 |

## 4. 입력 데이터

MVP에서는 한 번에 하나의 문서를 처리한다. 텍스트형 문서는 직접 추출하고, 스캔 PDF와 이미지 문서는 OCR로 텍스트를 변환한다.

| 입력 데이터   | 형식                      | MVP 지원 여부 | 설명                         |
| -------- | ----------------------- | --------- | -------------------------- |
| 텍스트형 PDF | `.pdf`                  | 지원        | 문서 내부에 선택 가능한 텍스트가 포함된 PDF |
| 텍스트 파일   | `.txt`                  | 지원        | UTF-8 텍스트 파일               |
| Word 문서  | `.docx`                 | 지원        | 텍스트가 포함된 Word 문서           |
| 스캔 PDF   | `.pdf`                  | 지원        | OCR로 문서 이미지를 텍스트로 변환       |
| 이미지 문서   | `.jpg`, `.jpeg`, `.png` | 지원        | OCR로 이미지의 글자를 텍스트로 변환      |

## 5. 핵심 기능

| 기능 ID | 기능명           | 설명                                                 | 우선순위 |
| ----- | ------------- | -------------------------------------------------- | ---- |
| F-01  | 파일 업로드        | 웹 화면에서 문서 파일을 업로드한다.                               | 높음   |
| F-02  | 지원 형식 및 파일 검증 | 확장자, 실제 파일 형식, 파일 크기, 손상 여부를 확인한다.                 | 높음   |
| F-03  | 텍스트 추출        | PDF, TXT, DOCX에서 텍스트를 추출한다.                        | 높음   |
| F-04  | OCR           | 스캔 PDF와 이미지 문서에서 글자를 추출한다.                         | 높음   |
| F-05  | 텍스트 정리        | 불필요한 공백과 반복 줄바꿈을 정리하고 원문의 의미가 훼손되지 않도록 텍스트를 정규화한다. | 높음   |
| F-06  | 요약 생성         | 한 줄 요약, 핵심 내용, 핵심 주제, 키워드, 수치·조건, 검토 필요 항목을 생성한다.  | 높음   |
| F-07  | 요약 내용 검증      | 요약 결과를 원문과 비교하여 근거 부족, 누락, 과장 또는 원문에 없는 내용을 확인한다.  | 높음   |
| F-08  | 결과 확인         | 사용자가 대시보드에서 요약 결과와 검증 결과를 확인한다.                    | 높음   |
| F-09  | 진행 상황 표시      | 문서 처리 상태를 사용자에게 표시한다.                              | 낮음   |
| F-10  | 실패 안내 및 재시도   | 처리 실패 원인을 안내하고 사용자가 다시 업로드할 수 있도록 한다.              | 낮음   |
| F-11  | 결과 저장         | 원문, 요약 결과, 검증 결과를 저장한다.                            | 낮음   |
| F-12  | 결과 공유         | 결과를 링크, 이메일 또는 이미지로 공유한다.                          | 낮음   |
| F-13  | 결과 다운로드       | 요약 결과와 검증 결과를 Markdown 파일로 다운로드한다.                 | 높음   |

## 6. 처리 흐름

| 순서 | 단계            | 설명                                              |
| -- | ------------- | ----------------------------------------------- |
| 1  | 문서 업로드        | 사용자가 하나의 문서 파일을 업로드한다.                          |
| 2  | 파일 검증         | 지원 형식, 파일 크기, 손상 여부, 암호화 여부를 확인한다.              |
| 3  | 텍스트 추출 또는 OCR | 텍스트형 문서는 텍스트를 추출하고, 스캔 PDF·이미지는 OCR로 텍스트를 변환한다. |
| 4  | 텍스트 정리        | 공백과 반복 줄바꿈 등을 정리하여 요약 입력을 만든다.                  |
| 5  | 문서 요약         | OpenAI를 사용하여 문서의 핵심 내용을 구조화하여 요약한다.             |
| 6  | 요약 내용 검증      | 요약 결과를 원문과 비교하고 검토 필요 사항을 표시한다.                 |
| 7  | 결과 표시         | 대시보드에 요약 결과와 검증 결과를 표시한다.                       |
| 8  | 결과 다운로드       | 사용자가 요약 결과와 검증 결과를 Markdown 파일로 다운로드한다.         |

처리 중 파일 검증, 텍스트 추출, OCR, 요약 또는 검증에 실패하면 실패 원인을 안내하고 사용자가 파일을 다시 업로드할 수 있도록 한다. 자동 재시도는 MVP 범위에서 제외한다.

## 7. 출력 결과

| 출력 결과   | 형식          | 설명                                  |
| ------- | ----------- | ----------------------------------- |
| 전체 요약   | 대시보드 텍스트    | 문서의 주제와 한 줄 요약을 표시한다.               |
| 핵심 내용   | 목록 또는 텍스트   | 문서에서 확인된 주요 내용을 표시한다.               |
| 키워드     | 키워드 목록      | 문서를 대표하는 핵심 키워드를 표시한다.              |
| 수치·조건   | 목록 또는 표     | 원문에 포함된 중요한 수치와 조건을 표시한다.           |
| 검증 결과   | 상태, 설명, 근거  | 누락, 과장, 원문 근거 부족 또는 검토 필요 사항을 표시한다. |
| 실패 결과   | 웹 화면 안내     | 실패 원인과 사용자가 취할 조치를 표시한다.            |
| 다운로드 파일 | Markdown 파일 | 요약 결과와 검증 결과를 포함하여 사용자의 기기에 다운로드한다. |

## 8. MVP 범위

MVP 범위는 F-01부터 F-08까지에 OCR과 결과 다운로드를 포함하여 F-01\~F-08, F-13으로 구성한다.

| 구분 | 기능            | 이유                                      |
| -- | ------------- | --------------------------------------- |
| 포함 | F-01 파일 업로드   | 서비스 사용의 시작점이므로 필요하다.                    |
| 포함 | F-02 파일 검증    | 지원하지 않는 파일과 손상된 파일을 사전에 차단해야 한다.        |
| 포함 | F-03 텍스트 추출   | 텍스트형 문서에서 요약할 원문을 확보해야 한다.              |
| 포함 | F-04 OCR      | 스캔 PDF와 이미지 문서도 처리할 수 있도록 한다.           |
| 포함 | F-05 텍스트 정리   | 요약 품질을 높이기 위해 입력 텍스트를 정리해야 한다.          |
| 포함 | F-06 요약 생성    | 서비스의 핵심 가치인 문서 요약을 제공한다.                |
| 포함 | F-07 요약 내용 검증 | 요약의 신뢰성을 확인할 수 있도록 한다.                  |
| 포함 | F-08 결과 확인    | 사용자가 요약 및 검증 결과를 확인해야 한다.               |
| 포함 | F-13 결과 다운로드  | 영구 저장 없이 사용자가 결과를 보관할 수 있게 한다.          |
| 제외 | F-09 진행 상황 표시 | 3시간 MVP에서는 결과 화면을 우선 구현한다.              |
| 제외 | F-10 자동 재시도   | MVP에서는 실패 원인과 재업로드 안내만 제공한다.            |
| 제외 | F-11 결과 저장    | 로그인·데이터베이스 없이 일회성 처리를 우선한다.             |
| 제외 | F-12 결과 공유    | 링크·이메일·이미지 공유는 핵심 요약 기능 검증 후 후순위로 구현한다. |

## 10. 확인 필요 사항

| 항목        | 결정 내용 또는 확인할 내용                                       |
| --------- | ----------------------------------------------------- |
| 입력 제한     | 한 번에 하나의 파일, 최대 10MB, PDF 최대 100페이지를 기본 제한으로 둔다.      |
| 텍스트 길이    | 추출 후 텍스트가 약 100,000자를 초과하면 처리하지 않고 안내한다.              |
| 저장 여부     | MVP에서는 원문·결과를 영구 저장하지 않고 요청 처리 후 삭제한다.                |
| 결과 보관     | 서버에 영구 저장하지 않고 Markdown 다운로드만 제공한다.                   |
| 개인정보      | 개인정보나 민감 문서 업로드를 제한하고, 로그에는 원문·API Key·토큰을 남기지 않는다.   |
| 외부 전송     | 요약을 위해 추출 텍스트가 OpenAI 서비스로 전송될 수 있음을 사용자에게 안내한다.      |
| AI 제공자·모델 | AI 제공자는 OpenAI로 결정한다. 사용할 모델명과 세부 버전은 프로젝트 환경에서 확정한다. |
| 처리 방식     | MVP에서는 한 파일을 요청 단위로 동기 처리하고, 처리 시간 초과 시 실패 안내를 제공한다.  |
| 요약 언어     | MVP에서는 한국어 요약을 기본값으로 한다.                              |

## 제약과 데이터 취급

* 한 번에 하나의 파일만 처리한다.

* 최대 파일 크기는 10MB로 제한한다.

* PDF는 최대 100페이지로 제한한다.

* 추출된 텍스트가 약 100,000자를 초과하면 처리하지 않고 사용자에게 안내한다.

* MVP에서는 원문과 결과를 영구 저장하지 않는다. 요청 처리에 필요한 임시 파일은 처리 완료 또는 실패 후 삭제한다.

* 개인정보와 민감정보가 포함된 문서는 업로드하지 않도록 안내한다.

* OpenAI 서비스를 사용할 경우 추출 텍스트가 외부로 전송될 수 있음을 사용자에게 알린다.

* 결과는 서버에 저장하지 않고 사용자의 기기에 Markdown 파일로 다운로드한다.

* 로그에는 원문, 개인정보, API Key, 토큰, 비밀번호를 기록하지 않는다.

* 처리 시간 초과나 외부 AI 오류가 발생하면 내부 오류 내용을 노출하지 않고 사용자용 오류 메시지를 표시한다.

## 확인 필요 사항과 단계 판정

| 미정 사항         | 담당·확인 방법·시점                  | 영향·진행 가능 범위                                 |
| ------------- | ---------------------------- | ------------------------------------------- |
| AI 모델명·세부 버전  | 프로젝트 환경과 비용을 확인한 뒤 확정        | OpenAI 제공자 기준으로 모델 연동을 진행하되 모델 교체가 가능하도록 구성 |
| 파일 제한의 최종값    | 샘플 문서로 처리 시간과 비용을 확인         | 기본값 10MB·100페이지·100,000자로 MVP 진행 가능         |
| OCR 품질과 처리 시간 | 샘플 스캔 문서로 인식률과 처리 시간을 확인     | OCR은 MVP에 포함하되 품질이 낮은 문서는 검증 불가로 안내         |
| 다운로드 형식       | 시연 시 Markdown 파일의 내용과 형식을 확인 | 서버 저장 없이 결과 다운로드 방식으로 MVP 진행 가능             |

* 판정: 보완 필요

* 근거: 핵심 기능과 MVP 범위는 정의되었고 OpenAI·100페이지·비영구 저장·OCR 포함을 결정했다. 다만 모델명과 OCR 품질은 실제 샘플 검증이 필요하다.

* 실행 검증: 해당 없음(요구사항 정의 단계)

* 다음 권장 작업: F-01부터 F-08, F-13을 기능 분해하고 각 기능의 입력·처리·출력·실패 흐름을 구체화한다.
