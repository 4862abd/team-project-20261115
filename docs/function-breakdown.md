## 2. 기능 범위 요약

이 프로그램은 지원 문서를 입력받고, 문서의 핵심 내용과 검증 결과를 분석한 뒤, 입력 종류에 맞는 결과 파일을 사용자에게 제공한다. 원본과 결과는 DB에 저장하지 않으며, 처리용 임시 파일도 저장하지 않는다.

### 2.1 기능 계층도

```text
문서 요약 프로그램
├─ 1. 문서 입력
│  ├─ 1.1 문서 업로드
│  ├─ 1.2 업로드 문서 형식 확인
│  ├─ 1.3 파일 크기 제한 확인
│  ├─ 1.4 페이지 수 제한 확인
│  ├─ 1.5 스프레드시트 시트 수 제한 확인
│  └─ 1.6 입력 자료 비저장
├─ 2. 텍스트 추출
│  ├─ 2.1 PDF 추출
│  ├─ 2.2 DOCX 추출
│  ├─ 2.3 TXT 추출
│  ├─ 2.4 XLSX·XLS 추출
│  ├─ 2.5 CSV 추출
│  └─ 2.6 공통 결과 정리
├─ 3. 텍스트 요약
│  ├─ 3.1 요약 입력 확인 및 기준 구성
│  ├─ 3.2 긴 원문 처리
│  ├─ 3.3 구조화 요약 생성
│  └─ 3.4 원문 근거 및 품질 확인
├─ 4. AI 검증 결과 제공
│  ├─ 4.1 비교 입력 확인
│  ├─ 4.2 원문·분석·요약 비교
│  ├─ 4.3 검토 후보와 근거 정리
│  └─ 4.4 검토 결과 제공
├─ 5. 결과 파일 제공
│  ├─ 5.1 PDF 결과 생성
│  ├─ 5.2 XLSX 결과 생성
│  └─ 5.3 결과 파일 다운로드
└─ 6. 처리 자료 폐기
   └─ 6.1 원본 및 결과 비저장
```

## 3. 기능 상세

### 3.1 문서 입력

**정의:** 사용자가 요약할 문서를 업로드하고 업로드된 문서의 지원 형식 여부를 확인하는 기능이다.

| 기능 ID | 하위 기능 | 기능 설명 | 확정 기준·제약 |
| --- | --- | --- | --- |
| IN-01 | 문서 업로드 | 사용자가 요약할 문서 파일을 프로그램에 입력한다. | 지원 확장자: `.txt`, `.docx`, `.pdf`, `.xlsx`, `.xls`, `.csv` |
| IN-02 | 업로드 문서 형식 확인 | 업로드 문서의 확장자를 지원 형식 목록과 대조한다. 파일 내용 형식은 검사하지 않는다. | 확장자 기준 확인으로 확정 |
| IN-03 | 파일 크기 확인 | 업로드 파일 크기가 제한 이내인지 확인한다. | 파일당 최대 10MB |
| IN-04 | 페이지 수 확인 | PDF는 텍스트 추출 과정에서 실제 페이지 수를 확인한다. TXT·DOCX·XLSX·XLS·CSV는 페이지 제한 없이 파일 크기만 확인한다. | PDF 최대 20페이지. 기타 형식은 페이지 제한 없음 |
| IN-05 | 시트 수 확인 | 스프레드시트의 표시 시트 수 제한을 확인하고 숨김 시트는 요약 대상에서 제외한다. | 최대 10개 표시 시트. CSV는 1개 시트로 계산 |
| IN-06 | 입력 자료 비저장 | 원본 문서와 처리용 임시 파일을 저장하지 않는다. | DB 및 임시 파일 저장 제외는 확정. 실패 시 메모리 자료 즉시 폐기. 초안 가정: 성공은 다운로드 응답 완료 후, 취소는 취소 확인 즉시 폐기 |

#### 3.1.1 입력 처리 흐름

1. 사용자가 지원 문서 중 요약할 파일을 업로드한다.
2. 확장자와 파일 크기(최대 10MB)를 확인한다.
3. 문서 내용을 추출한다.
4. PDF는 텍스트 추출 과정에서 실제 페이지 수가 최대 20페이지인지 확인한다. TXT·DOCX·Excel에는 페이지 제한을 적용하지 않는다.
5. 스프레드시트는 숨김 시트를 요약 대상에서 제외하고 표시 시트가 최대 10개인지 확인한다. CSV는 1개 시트로 계산한다.
6. 제한을 초과하거나 지원하지 않는 경우 실패 메시지를 표시하고 분석을 진행하지 않는다.
7. 실패하면 관련 메모리 자료를 즉시 폐기한다. 성공 시 다운로드 응답 완료 후, 취소 시 취소 확인 즉시 폐기하는 것을 초안 가정으로 한다.
8. 입력 자료는 DB 또는 임시 파일로 저장하지 않는다.

> 제한 초과 또는 파일 읽기 실패 시 사용자에게 원인과 제한 기준을 포함한 실패 메시지를 표시한다. 자동 재시도는 하지 않으며, 사용자가 재시도 여부를 결정한다. 아래 문안은 초안이다.

| 실패 상황 | 메시지 초안 |
| --- | --- |
| 지원하지 않는 확장자 | 지원하지 않는 파일 형식입니다. TXT, DOCX, PDF, XLSX, XLS, CSV 파일을 선택해 주세요. |
| 10MB 초과 | 파일 크기가 10MB를 초과했습니다. 10MB 이하의 파일을 선택해 주세요. |
| 페이지 수 초과 | 추출된 문서 분량이 20페이지 제한을 초과했습니다. 분량을 줄인 뒤 다시 시도해 주세요. |
| 표시 시트 수 초과 | 숨김 시트를 제외한 시트가 10개를 초과했습니다. 시트 수를 줄인 뒤 다시 시도해 주세요. |
| 읽기 실패 | 파일 내용을 읽지 못했습니다. 파일이 손상되지 않았는지 확인한 뒤 다시 시도해 주세요. |
| 분석 실패 | 문서 분석 중 오류가 발생했습니다. 잠시 후 다시 시도해 주세요. |

### 3.2 텍스트 추출

**정의:** 문서 입력 기능에서 확장자와 업로드 크기 확인이 끝난 PDF, DOCX, TXT, XLSX, XLS, CSV를 읽고 AI 분석에 사용할 공통 결과로 변환한다. 파일 형식별 추출과 공통 결과 정리는 별도 기능으로 분리한다.

| 기능 ID | 하위 기능 | 기능 설명 | 입력 | 출력·연결 |
| --- | --- | --- | --- | --- |
| EXT-01 | PDF 텍스트 추출 | PDF의 텍스트 본문을 추출한다. OCR은 수행하지 않으며 실제 페이지 수가 최대 20페이지인지 확인한다. | 검증된 `.pdf` | 추출 결과와 실제 페이지 수를 공통 결과 정리 기능으로 전달 |
| EXT-02 | DOCX 텍스트 추출 | DOCX 본문에서 AI가 분석할 텍스트를 추출한다. 페이지 제한은 적용하지 않는다. | 검증된 `.docx` | 추출 결과를 공통 결과 정리 기능으로 전달 |
| EXT-03 | TXT 텍스트 추출 | TXT 파일에서 AI가 분석할 텍스트를 추출한다. 페이지 제한은 적용하지 않는다. | 검증된 `.txt` | 추출 결과를 공통 결과 정리 기능으로 전달. 인코딩 규칙은 구현 단계에서 결정 |
| EXT-04 | XLSX·XLS 데이터 추출 | 표시 시트의 이름, 헤더, 데이터 행 수와 요약 분석에 필요한 셀 내용을 추출한다. 숨김 시트는 요약 대상에서 제외한다. | 검증된 `.xlsx`, `.xls` | 표시 시트별 추출 결과를 공통 결과 정리 기능으로 전달 |
| EXT-05 | CSV 데이터 추출 | CSV 내용을 하나의 시트에 해당하는 데이터로 추출한다. | 검증된 `.csv` | 헤더·행 데이터가 포함된 추출 결과를 공통 결과 정리 기능으로 전달 |
| EXT-06 | 공통 결과 정리 | 형식별 추출 결과를 LLM AIagent API에 전달할 수 있도록 공통 결과로 구성한다. 엑셀은 표시 시트명·헤더·행 수와 셀 내용을 구분한다. | EXT-01~EXT-05의 결과 | PDF 페이지 제한 확인 및 AIagent API 호출에 전달. API 요청 스키마와 본문 순서·서식·원문 위치 표현은 구현 단계에서 결정 |

#### 3.2.1 입력 조건 및 연결

- 확장자 확인과 10MB 업로드 제한은 기존 `IN-02`, `IN-03`에서 처리하며 이 기능에서 중복 수행하지 않는다.
- 이 기능은 문서 입력에서 확인된 지원 파일을 전달받는다.
- PDF 페이지 제한 확인은 기존 `IN-04`가 소유하며, 텍스트 추출 결과의 실제 페이지 수를 받아 수행한다. TXT·DOCX·Excel에는 페이지 제한을 적용하지 않는다.
- 스프레드시트는 숨김 시트를 시트 수 계산과 요약 대상에서 제외하고, 표시 시트 수를 최대 10개로 제한한다. CSV는 1개 시트로 계산한다(`IN-05`).
- 원본 파일 및 임시 파일을 저장하지 않는다(`IN-06`). 추출 실패 시 관련 메모리 자료를 즉시 폐기한다.
- OCR은 수행하지 않는다. 암호화·빈 파일·손상 파일, 인코딩, 표·목록·문단 구조 보존 방식은 구현 세부사항으로 결정이 필요하다.

### 3.3 텍스트 요약

**정의:** 원문 텍스트와 AI 분석 결과를 바탕으로 문서 개요, 핵심 내용, 결론 또는 핵심 메시지를 구조화해 생성한다. 요약은 원문의 의미를 바꾸거나 원문에 없는 사실을 추가하지 않는다.

| 기능 ID | 하위 기능 | 기능 설명 | 입력·출력 |
| --- | --- | --- | --- |
| SUM-01 | 요약 입력 확인 | 원문 텍스트와 AI 분석 결과의 존재 여부, 형식, 길이를 확인한다. 입력이 없거나 불충분하면 보완 요청 또는 생성 불가 사유를 반환한다. | 입력: 공통 추출 결과, AI 분석 결과. 출력: 요약 가능 여부 및 확인 사유 |
| SUM-02 | 요약 기준 구성 | 핵심 내용을 중요도에 따라 계층형으로 구성한다. 구체적인 중요도 단계와 판정 기준은 구현 단계에서 정한다. | 중요도 세부 기준은 구현 단계에서 결정 |
| SUM-03 | 긴 원문 처리 | 긴 원문을 구간별로 다루면서 문맥을 유지하고 필요한 내용을 추출한다. | 구간 길이, 문맥 유지 방법, 선택 기준은 결정 필요 |
| SUM-04 | 구조화 요약 생성 | 문서 개요, 핵심 내용, 결론 또는 핵심 메시지를 구성한다. 원문에 명시적 결론이 없으면 결론을 만들지 않고 확인할 수 없음을 표시한다. | 출력: 구조화 요약 |
| SUM-05 | 원문 근거 확인 | LLM AIagent API 결과에 포함된 원문 근거를 사용해 요약 내용의 뒷받침 여부를 확인하고 누락, 의미 왜곡, 과장, 원문에 없는 사실 추가를 점검한다. | 근거 필드 형식과 검증 임계값은 구현 단계에서 결정 |
| SUM-06 | 요약 품질 확인 | 정확성, 완전성, 가독성, 분량, 형식 준수 여부를 확인한다. | 품질 기준과 재생성 횟수는 결정 필요 |
| SUM-07 | 요약 결과 구조화 | 요약 결과를 지정된 항목과 형식에 맞춰 후속 검증·표시 기능에 전달한다. | 필드 구조 및 필수 항목은 결정 필요 |

#### 3.3.1 정상 처리 흐름

1. 원문 텍스트와 AI 분석 결과를 확인한다.
2. 요약 기준을 구성한다. 구체 기준 값이 필요한 경우 미정 사항을 적용한다.
3. 긴 원문은 문맥을 고려해 구간별 처리 대상으로 나눈다.
4. 문서 개요, 핵심 내용, 결론 또는 핵심 메시지를 생성한다.
5. 각 요약 내용이 원문에서 뒷받침되는지 점검한다.
6. 정확성·완전성·가독성·분량·형식 준수 여부를 확인한다.
7. 지정 항목에 맞게 결과를 구조화해 후속 기능으로 전달한다.

#### 3.3.2 예외 처리

| 상황 | 처리 기준 | 미정 사항 |
| --- | --- | --- |
| 원문 또는 분석 결과가 없거나 불충분함 | 보완을 요청하거나 생성 불가 사유를 안내한다. | 판단 기준, 안내 문구, 재시도 흐름 |
| AI 분석 결과와 원문이 다름 | 원문을 기준으로 하거나 확인이 필요한 내용으로 표시한다. | 차이를 판정하는 기준과 표시 형식 |
| 원문에 명시적 결론이 없음 | 결론을 임의로 생성하지 않고 확인 불가로 표시한다. | 표시 문구와 결과 구조 |
| 요약 품질 기준 미달 | 품질 문제가 있는 결과를 확인 대상으로 처리한다. | 임계값, 자동 재생성 여부와 횟수 |

### 3.4 AI 검증 결과 제공

**정의:** 생성된 요약을 원문 및 AI 분석 결과와 비교해 사람이 최종 확인해야 할 후보와 근거를 제공한다. AI가 사실관계를 최종 확정하지 않는다.

| 기능 ID | 하위 기능 | 기능 설명 | 입력·출력 |
| --- | --- | --- | --- |
| VER-01 | 검증 입력 확인 | 원문, AI 분석 결과, 요약 결과의 존재 여부·형식·길이를 확인한다. | 누락 시 생성 상태와 오류 처리 방식은 결정 필요 |
| VER-02 | 원문·분석·요약 비교 | 각 요약 항목을 원문 및 AI 분석 결과와 비교한다. | 비교 단위와 상충 판정 기준은 결정 필요 |
| VER-03 | 검토 후보 식별 | 누락, 불일치, 과장, 수치 오류 등 사람이 확인할 항목을 후보로 식별한다. | 후보 분류 및 심각도 기준은 결정 필요 |
| VER-04 | 근거 정리 | LLM AIagent API 결과에 포함된 원문 근거를 검토 후보와 연결한다. | API 근거 필드와 인용 범위·위치 표현은 구현 단계에서 결정 |
| VER-05 | 검증 결과 제공 | 후보, 결과, 근거를 사람이 확인할 수 있는 검증 결과로 제공한다. AI 판단은 최종 사실 판정으로 표시하지 않는다. | 표시 상태·문구·결과 스키마는 결정 필요 |
| VER-06 | 검증 실패 처리 | 원문·분석 결과·요약 중 필수 입력이 없거나 비교할 수 없으면 결과 생성 불가 또는 확인 필요 상태로 전달한다. | 상태 구분과 사용자 안내는 결정 필요 |

#### 3.4.1 정상 처리 흐름

1. 원문, AI 분석 결과, 요약 결과를 확인한다.
2. 요약 항목을 원문 및 분석 결과와 비교한다.
3. 누락·불일치·과장·수치 오류 후보를 식별한다.
4. 각 후보에 해당하는 원문 근거를 연결한다.
5. AI가 확정 판정하지 않는 검토 후보로 정리해 결과 표시 기능에 전달한다.

#### 3.4.2 예외 처리 및 요구사항 연결

- 비교 입력이 없거나 형식이 맞지 않는 경우, 검증 결과를 생성할 수 없는 이유를 후속 기능에 전달한다. 구체 상태·문구는 미정이다.
- 외부 자료를 이용한 사실 확인은 이 기능 정의에 포함하지 않는다. 현재 요구사항의 문서 내부 검증 범위와 동일한지 확인이 필요하다.
- 기존 요구사항 `R-04`는 결과 파일에 검증 결과와 근거를 포함한다고 규정하지만, 요약과 분석 결과 비교, 후보 분류, 근거 위치 등의 세부 기준은 정의하지 않는다. 새 `R-ID`나 `T-ID`는 임의로 만들지 않았다.

| 기능 ID | 기존 요구사항 연결 | 연결 상태 |
| --- | --- | --- |
| VER-01~VER-06 | R-04 | 검증 결과 제공의 상위 요구사항만 연결. 세부 수용 기준은 요구사항 재정의 필요 |

### 3.5 결과 파일 제공

#### 3.5.1 결과 형식

| 입력 확장자 | 결과 확장자 | 비고 |
| --- | --- | --- |
| 전체 지원 입력 형식 | `.pdf` | 문서 정보·요약·근거를 포함한 결과 |
| `.xlsx`, `.xls`, `.csv` | `.xlsx` 추가 제공 | 기존 승인된 결과 시트명과 헤더 구성 유지 |

#### 3.5.2 문서 요약 PDF 구성안

다음 항목은 승인된 결과 구성이다.

1. 문서 제목
2. 전체 요약
3. 대단락·중단락·소단락별 핵심 내용
4. 주요 인물·기관명, 날짜, 수치 등 핵심 정보
5. 검증 항목, 결과, 원문 근거

초안 서식: A4 세로 방향, 제목과 전체 요약을 앞부분에 두고 대·중·소단락을 시각적으로 구분한다. 검증 결과는 확인 항목·결과·근거를 표로 제시하고 페이지 번호를 표시한다.

#### 3.5.3 스프레드시트 요약 XLSX 구성안

다음 시트 구성을 사용한다.

| 시트명 | 헤더 | 포함 정보 |
| --- | --- | --- |
| 전체 요약 | 항목, 요약 내용, 검증 결과 | 통합 문서 또는 CSV 데이터 전체의 요약 및 검증 결과 |
| 시트별 요약 | 원본 시트명, 헤더, 데이터 행 수, 주요 내용, 검증 결과 | 표시 시트별 구조와 요약. CSV는 단일 데이터 시트로 취급 |

| 기능 ID | 하위 기능 | 기능 설명 | 확정 기준·제약 |
| --- | --- | --- | --- |
| OUT-01 | PDF 결과 생성 | 전체 지원 입력 형식의 결과 정보를 PDF 파일로 구성한다. | PDF는 모든 입력 형식의 다운로드 결과에 포함한다. 요약·근거를 포함하고 원문 전체는 제외 |
| OUT-02 | XLSX 결과 생성 | XLSX·XLS·CSV 입력의 분석 결과를 XLSX 파일로 구성한다. | 입력 대비 출력 형식, 시트명, 헤더, 포함 내용은 확정 |
| OUT-03 | 결과 파일 다운로드 | 결과 생성 성공 직후 파일을 다운로드 응답으로 제공한다. | 초안 파일명: 원본 파일명에서 확장자를 제외한 이름에 `_summary.pdf` 또는 `_summary.xlsx`를 붙인다. 응답 완료 후 메모리 자료를 폐기한다. |

## 4. 예외 및 제한 처리

| 상황 | 요구된 동작 | 미정 사항 |
| --- | --- | --- |
| 지원하지 않는 확장자 또는 10MB 초과 | 추출 전에 거부하고 실패 메시지를 표시한다. 사용자 재시도 여부를 기다린다. | 문안은 초안 메시지 참조 |

| 표시 시트 10개 초과 | 숨김 시트를 제외한 시트 수를 확인하고 초과하면 이후 분석을 중단한다. CSV는 1개 시트로 계산하며 숨김 시트는 요약 대상에서 제외한다. | 해당 없음(확정) |
| 실제 파일 내용이 확장자와 다름 | 확장자만 확인하므로 사전 판별하지 않는다. 읽기 실패 시 실패 안내로 연결한다. | 손상·불일치 유형별 메시지 구분 여부 |
| PDF/DOCX/TXT/스프레드시트 읽기 실패 | 실패 메시지를 보여 주고 사용자가 재시도 여부를 결정하게 한다. 실패 즉시 메모리 자료를 폐기한다. PDF는 텍스트만 추출하며 OCR은 하지 않는다. | 빈 파일, 암호화 파일 등 유형별 세부 처리 |
| 원문 또는 AI 분석 결과가 없음·불충분 | 요약/검증 결과를 만들 수 없음을 알리거나 보완 입력을 요청한다. | 판정 기준과 사용자 안내 문구 |
| 원문과 AI 분석 결과가 서로 다름 | 요약 기능은 원문을 기준으로 처리하거나 확인 필요 내용을 표시하는 안을 제시한다. | 두 동작 중 적용할 기준을 결정해야 함 |
| 원문에 결론이 없음 | 결론을 만들어내지 않고 확인할 수 없음을 표시한다. | 표시 문구 및 결과 구조 |
| 요약에 근거가 없거나 의미 왜곡이 의심됨 | 품질 확인 단계에서 문제 후보로 다룬다. | 허용 기준과 재생성 여부·횟수 |
| 검증 입력이 누락되거나 비교할 수 없음 | 최종 사실 판정을 하지 않고 검증 생성 불가 또는 확인 필요 상태로 전달한다. | 상태명, 결과 표시 방식, 메시지 |

## 7. 설계 판정

- 판정: 확인 필요
- 근거: 지원 확장자와 확장자 확인 방식, 입력 상한, PDF 페이지 제한, 표시 시트 제한, PDF 텍스트 추출(OCR 제외), 숨김 시트 요약 제외, LLM AIagent API 사용, 중요도 기반 계층형 요약·검증, 출력 파일 형식과 구성, 실패 메시지 후 재시도 결정, DB·임시 파일 저장 제외가 확정되었다. API 계약과 중요도 단계, 세부 서식·메모리 폐기 정책은 구현 단계에서 구체화한다.
- 구현 여부: 구현하지 않음. 본 문서는 기능분해 설계 문서이다.
- 다음 권장 작업: 5절 초안 기본값을 검토하고 필요하면 수정한 뒤 기능 상세와 수용 기준을 확정한다.
